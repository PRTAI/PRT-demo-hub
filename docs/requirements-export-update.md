# 需求飞书文档、截止日期排序与 Excel 导出

## 导出后同步同一份飞书文档

项目经理首次单条导出或批量导出成功后，该文档成为需求的自动同步目标。后续修改需求状态、标题、正文、负责人、需求附件，或保存关联 Demo 的说明和文件，后台都会更新**同一个文档 ID 和链接**。新需求尚未导出时，详情提示项目经理先导出一次。

导出和同步统一使用文档创建者的飞书 `user_access_token`。同步已知文档时直接调用文档正文及附件接口，不读取 sample、不另建协作文档，也不管理协作者权限。知识库中的文档改名使用已记录的空间和节点 ID。`FEISHU_REQUIREMENT_WIKI_SAMPLE_URL` 不再是自动同步的前置条件，旧配置可保留。

后台每 5 秒处理待同步任务。状态等普通文本变化直接更新原区块，保留附件；结构或附件变化时分批写入新内容，完成后仅清理平台记录的旧区块。相同附件复用当前文档中的素材。人工补充请放在平台生成区块之外；平台管理区块内的手动修改会在后续同步时被覆盖。

文档 ID、内容版本、区块 ID、附件状态和重试进度保存在数据库。网络错误最多自动重试 5 次，失败不阻塞需求保存或 Demo 上传。商务、项目经理、管理员可在需求详情点击“同步当前内容”，管理员也可在平台设置查看和重试。

**用户授权只保存在内存中。** 授权到期、退出登录、容器重启后，需原导出项目经理重新授权，再点击“同步当前内容”。授权者停用或失去项目经理角色时停止写入。其他项目经理可重新导出建立新的同步目标；系统不会自动退回应用身份尝试写入。普通平台登录不能替代文档授权。

升级时自动接入已有成功导出的文档，保留链接和内容；如果旧文档的原始区块已被移动或修改，无法安全识别同步区域，会提示重新导出一次。旧 sample 协作文档保留，但正常平台流程不再创建或更新另一份 sample 文档。

## 截止日期排序

需求中心和“我的需求”均在服务器分页前排序：未关闭需求在前，已关闭需求在最后；各组内按截止日期从早到晚排列，未设日期的靠后；日期相同按更新时间倒序。已关闭需求卡片整体使用灰色，搜索和状态筛选仍然生效。

## 导出表格

只有 `pm` 角色（产品／项目经理）可见“导出 Excel”，后端也校验此权限。操作步骤：

1. 使用搜索、状态或“我的需求”筛选，点击“导出 Excel”。范围包含全部匹配需求，不限当前页；表格行和待导出的正文在此时固定。
2. 按提示完成本人的飞书文档授权，返回列表后点击“已授权，继续本批导出”。同一标签页刷新可恢复批次。
3. 后台逐条准备飞书文档，全部成功后下载八列表格。相同用户、相同位置且内容已同步的文档直接复用；未同步的当前内容可以重新导出，成功后成为新的同步目标。
4. 出错时点击“重试未完成项”；已完成项不重复创建。个人授权失效时，重新授权后继续原批次。创建结果不确定时停止新建，先检查目标位置。

批次保存发起时的范围和表格内容；成功导出的文档随后会随平台变化继续同步。需要最新 Excel 时请重新筛选并发起批次。批次临时记录保留 7 天，不删除需求、飞书文档或原始文件。

表格按照《平台导出需求模版》包含以下八列，顺序固定，**一条需求一行**：

| 列 | 内容 |
| --- | --- |
| 标题 | 需求名称，带打开该需求详情的超链接。 |
| 需求说明 | 平台保存的需求正文；正文仅为一个 HTTP(S) 链接时可直接点击；缺失时为 `/`。 |
| 需求文档 | 已上传的需求文件名称，多个文件换行排列；点击打开需求详情，在其中查看和下载全部附件；没有附件时为 `/`。 |
| 商务负责人 | 平台记录的商务负责人，多人以“、”分隔，未指定时为 `/`。 |
| 研发负责人 | 平台记录的研发负责人，多人以“、”分隔，未指定时为 `/`。 |
| 进度 | 进行中、待更新、已交付或已关闭。 |
| 截止日期 | 真实 Excel 日期，显示为 `yyyy-mm-dd`，可排序；未设置时为 `/`。 |
| 样例 | 关联且当前账号可见的 Demo 名称。一个 Demo 时点击直达 Demo 详情；多个 Demo 换行排列，点击进入需求详情查看全部样例；没有可见样例时为 `/`。 |

多个样例不再拆成多行，避免重复统计需求；同一个 Demo 关联多条需求时，在各条需求的“样例”列出现。模板中的“举例”“示图”及示例截图仅用于说明，不加入导出业务列。

导出前先准备飞书文档，表格保持八列。文档入口在需求详情，也可到目标飞书位置按需求名称查找。历史 Demo 需先关联需求，才会出现在该需求的正文和表格样例中。

需求卡片、需求详情和 Demo 详情提供“复制链接”。优先使用 `PUBLIC_APP_ORIGIN`，否则使用 `APP_ORIGIN`。链接不会额外授予权限，登录后按原查看和下载权限访问。

## 导出单条需求

项目经理打开需求详情，点击“导出到我的飞书云文档”；配置目标知识库后为“导出到指定飞书目录”。首次按提示授权，返回需求后再次导出。其他角色不显示按钮。

文档名称只使用需求名称。结构为：需求信息 → 需求内容 → 负责人 → 需求文档 → 数据简介 → 数据说明 → 数据量级 → 成本预估 → 难度说明 → 注意事项 → Demo。使用飞书原生标题、列表、代码块和超链接，需求文档和 Demo 上传为真实附件。

失败后重试接续已记录的文档及附件进度。20 MB 以上文件分片上传，全部文件完成后才算成功；飞书自身空间及附件限制仍适用。成功导出后，该文档开始随平台更新。相同内容重复导出复用链接；重新导出成功的新文档会取代之前的自动同步目标。

## 将单条和批量导出放到指定知识库目录

默认保存在当前项目经理的个人云文档根目录。统一放到指定知识库节点下面时，在部署机 `.env` 设置：

```dotenv
FEISHU_REQUIREMENT_EXPORT_WIKI_PARENT_URL=https://zi4kl3ktexa.feishu.cn/wiki/UUsWwv96viopGXkfgHFcFyi8ncf
```

用当前项目经理账号确认能打开该节点并在其下面新建文档。在飞书开放平台为同一应用开通并发布**用户身份**权限：

- `docx:document`：创建、读取和编辑新版文档。
- `docs:document.media:upload`：上传附件到文档。
- `wiki:wiki`：仅指定知识库模式需要，用于初次创建节点及后续改名。

更新并重建容器后，由项目经理重新授权。`FEISHU_REQUIREMENT_EXPORT_WIKI_PARENT_URL` 留空则新导出回到个人根目录。修改默认位置不会移动已导出文档，也不会改变已经开始的批次；已有文档继续在原位置同步。文档访问范围由飞书目录和共享设置控制，平台不再自动增删协作者。

## Windows Docker 更新

同步最新完整源码，保留部署机 `.env`。在 PowerShell 执行：

```powershell
$ErrorActionPreference = 'Stop'
Set-Location 'J:\PRT-demo-hub-test'
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File '.\scripts\update-docker.ps1' `
  -ProjectDirectory 'J:\PRT-demo-hub-test' `
  -BackupDirectory 'J:\PRT-backups'
if ($LASTEXITCODE -ne 0) { throw '更新失败，请查看上方报错' }
Invoke-RestMethod 'http://127.0.0.1:8001/api/health' -TimeoutSec 15
```

本次无需新增环境变量，数据库自动升级。务必同步新增的 `server/requirement-document-sync.mjs`。完整命令及故障排查见 [Windows Docker 更新手册](windows-docker-guide.md#更新当前已运行的容器并保留旧数据)。

## 批量导出的权限与失败排查

单条导出、批量导出和文档同步均使用项目经理用户授权。如果导出可用而同步仍提示读取 sample 或应用身份协作者权限，请确认已更新容器并强制刷新页面；新版同步不走该路径。

同步提示重新授权时，由原导出项目经理在需求详情点击“重新授权飞书文档”，返回后点击“同步当前内容”。错误 `99991672` 需确认上述用户身份权限已发布生效、该账号仍能编辑目标文档，再重新授权；无需仅为同步已导出文档另加应用身份的 sample 知识库权限。

没有成功导出记录时，请项目经理先导出一次。旧文档无法安全识别原始同步区块时，按提示重新导出，不手动清空文档或数据库。

`scripts/check-requirement-wiki.mjs` 只检查旧应用身份 sample 流程，不用于验证当前导出文档同步。

## 验收

1. 项目经理导出一条需求并打开链接，检查规定结构、准确名称、真实需求附件和 Demo 附件。
2. 将需求从进行中改为已交付，等待同步成功；刷新原飞书链接，确认状态变化、链接不变。
3. 修改关联 Demo 的说明，上传需求附件，确认更新同一份文档。在平台区块之外添加人工文字，确认后续结构变化仍保留人工内容。
4. 按筛选导出 Excel，检查八列及范围；商务、主管和员工不显示导出按钮。关闭需求后，卡片整体变灰并排在末尾。
5. 容器重启后修改需求，确认提示原导出者重新授权；授权并重试后继续原文档。

本地测试模拟飞书 API；实际企业账号的授权、附件和文档访问需部署后验收。

## 评论加载失败的排查

导出器只写入正文和附件，不复制模板中的评论 ID、区块 ID 或其他只读元数据。若仅导出文档刷新时报“评论加载失败”，请在浏览器开发者工具 Network 中选择 Fetch/XHR，刷新后提供评论请求的 Request URL、Status Code 和 Response 的 code/msg。`window.loadChunkI18n` 是语言包，不是错误响应。没有接口证据前不能判断为评论权限问题，也不应通过隐藏提示来代替修复。
