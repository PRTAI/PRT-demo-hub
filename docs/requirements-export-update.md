# 需求飞书文档、截止日期排序与 Excel 导出

## 发布时创建飞书文档

平台发布需求的输入项保持原样。每条新需求会在后台创建一份独立的飞书知识库新版文档，放在配置的 sample 所在目录，与 sample 平级。sample 本身保持原样，每条需求只创建一份协作文档。

新文档名称使用需求名称，初始正文只有两个部分：

- **需求简述**：使用需求名称，平台原来的完整需求正文继续保存在平台。
- **需求文档**：列出上传到平台的需求文件名称和下载链接，未上传时显示提示。文件仍保存在平台，点击链接需登录平台并具备该需求的查看权限。

负责人给关联 Demo 上传文件并保存说明后，平台自动在同一份飞书文档中追加 **Demo 内容（平台自动同步）** 区域，直接使用 DemoHub 已保存的数据，无需额外调用大模型，也无需在飞书重复录入：

- Demo 名称、归属人、版本号、当前状态、文件数量及平台详情链接。
- 简介，以及“数据说明”中的完整内容（含数据概述、数据格式）。
- 成本预估、难度说明、注意事项。

草稿、待审核、已退回和已发布版本均可同步，以同一个 Demo **最新含文件且未下架的版本** 为准。仅填写说明、尚未上传任何文件的 Demo 不会提前写入文档。未保存的编辑内容、尚未采纳并保存的 AI 生成结果不会同步。数据说明的文字和 Markdown 原文保留，不会重新改写；原始压缩包、文件夹中的文件仍由平台存储，飞书中提供平台查看链接，访问和下载继续检查 Demo 权限。

后续保存说明、添加／移除文件、创建新版本、审核发布／打回／下架，以及绑定／解绑需求都会自动更新。一个需求关联多个 Demo 时汇总到同一文档；一个 Demo 关联多个需求时分别更新。下架或删除最新版本后，若存在更早的含文件且未下架版本则显示该版本；没有时移除该 Demo 的自动内容。解绑也会移除自动内容。

平台只更新自己记录的区块，不会重写整篇文档；内容变短时清空多余的平台段落，不删除人工区块。请保留“需求简述”“需求文档”和“Demo 内容（平台自动同步）”区域，在其他区块补充人工内容；对自动区块的手动编辑会在下次平台内容变化时被覆盖。

编辑需求名称、新增需求文件时同步同一份文档。负责人、发布人中当前启用的账号会获得文档编辑权限；新增、转发负责人后也会同步。移除或停用人员时仅撤销平台增加的直接权限，原有知识库继承权限及人工授予的权限仍由飞书管理。

任务及文档 ID 保存在数据库中，后台每 5 秒检查待同步任务。网络或权限失败不阻塞平台发布或 Demo 上传，自动重试 5 次。详情显示同步状态和错误，商务、项目经理、管理员可重试。管理员可在“平台设置 → 需求飞书文档同步”查看最近记录。重试复用已有文档；创建响应丢失时会按包含需求 ID 的临时标题查找恢复。Demo 区域新增段落的请求也会持久化，重试复用原请求，避免反复追加。

升级本身不会批量创建历史文档。历史需求可由商务、项目经理在需求详情点击“创建飞书文档”；项目经理也可以按下文的“导出 Excel”流程批量补建当前筛选范围内的历史需求文档，并写入已有关联 Demo 的说明。配置 sample 后新需求会自动创建。

## 截止日期排序

需求中心和“我的需求”使用相同规则，排序在服务器分页前完成：

1. 未关闭需求在前，已关闭需求在最后。
2. 各组内按截止日期从早到晚排列，已逾期的日期也参与排序。
3. 未设置截止日期的需求排在所在组的有日期需求之后。
4. 截止日期相同时，最近更新的在前；未设日期时也按最近更新排序。

搜索、状态筛选和“我的需求”权限继续生效。

## 导出表格

只有平台现有 `pm` 角色（产品／项目经理）能看到“导出 Excel”按钮，后端也检查相同权限。商务、普通主管、员工及仅管理员身份的账号无法导出；兼有 `pm` 的账号可导出。

在需求列表的搜索框、状态筛选右侧点击“导出 Excel”，平台会先同步飞书文档，再生成标准 `.xlsx` 文件：

1. 固定点击时的搜索、状态和“我的需求”范围，取**全部匹配结果**，不限于当前页，排序与需求列表一致。例如选择“进行中”，本批次只处理该状态的需求。同步过程中改变页面筛选、后续新增需求，不会改变已经开始的导出范围及表格行数据。
2. 为尚无文档的历史需求在 sample 同目录创建独立文档；已有文档复用并更新，不重复创建。先前仍在同步的文档任务会复用，失败项可以重试。
3. 写入需求简述、需求文档链接，以及已关联 Demo 的完整数据概述、数据格式、成本预估、难度说明、注意事项，并同步关联人员及发布人的编辑权限。使用平台已有内容，不额外调用大模型；人工新增的独立区块保留。
4. 页面显示本批次总数、已完成、等待和失败数。所有需求同步成功后，自动下载按新版需求模板生成的八列表格；表格中的标题、需求文档和样例使用平台详情链接。

批量创建在后台执行，不让一个 HTTP 请求一直等待飞书接口。同步期间可继续使用平台；同一标签页刷新后会恢复进度。“关闭进度”只关闭显示，已排队的文档同步仍会继续；重新导出会复用已创建文档。任务快照保留 7 天，过期后重新筛选导出，需求、文档和上传文件均保留。

如果有失败项，页面列出需求名称和原因，最多显示前 20 项。补齐飞书权限或解决网络问题后，点击“重试失败项”；完成项不重复处理。全部同步成功之前不会自动下载带缺失链接的表格。演示模式不写入外部飞书，仅导出已有数据并明确提示。

**旧 Demo 需要先与需求建立关联。** 尚未绑定的旧 Demo，请在需求详情绑定后再导出；文档同步只读取该需求已关联且含文件、未下架的 Demo 版本。

表格按照《平台导出需求模版》包含以下八列，顺序固定，**一条需求一行**：

| 列 | 内容 |
| --- | --- |
| 标题 | 需求名称，带打开该需求详情的超链接。 |
| 需求说明 | 平台保存的需求正文；正文仅为一个 HTTP(S) 链接时可直接点击；缺失时为 `/`。 |
| 需求文档 | 已上传的需求文件名称，多个文件换行排列；点击打开需求详情，在其中查看和下载全部附件；没有附件时为 `/`。 |
| 商务负责人 | 平台记录的商务负责人，多人以“、”分隔，未指定时为 `/`。 |
| 研发负责人 | 平台记录的研发负责人，多人以“、”分隔，未指定时为 `/`。 |
| 进度 | 进行中、待更新、已交付或已关闭。 |
| 截止日期 | 真实 Excel 日期，显示为 `yyyy-mm-dd`，可排序；未设置时为 `/`。 |
| 样例 | 关联且当前账号可见的 Demo 名称。一个 Demo 时点击直达 Demo 详情；多个 Demo 换行排列，点击进入需求详情查看全部样例；没有可见样例时为 `/`。 |

多个样例不再拆成多行，避免重复统计需求；同一个 Demo 关联多条需求时，在各条需求的“样例”列出现。模板中的“举例”“示图”及示例截图仅用于说明，不加入导出业务列。

原来的导出前飞书文档补建、同步和失败重试继续执行，协作文档仍可从平台需求详情打开；新版表格不再单列飞书文档链接。

需求卡片、需求详情和 Demo 详情提供“复制链接”。链接优先使用 `PUBLIC_APP_ORIGIN`，未设置时使用 `APP_ORIGIN`，不依赖临时下载 Token。尚未登录时，飞书登录完成会返回原需求或 Demo。分享链接不会额外授予权限，查看和下载继续按平台权限检查。

升级前尚未下载的旧版四列导出快照，需要重新点击“导出 Excel”，以免混入旧格式；原需求、Demo、飞书文档和上传数据均保留。

表格带筛选和冻结表头，名称、人员按文本保存，避免名称被表格软件解释成公式。

项目经理导出时继续应用页面筛选及 Demo 可见权限，选择“我的需求”后只导出关联自己的需求。文档在飞书中的访问权限由知识库和文档协作者设置控制。

开发接口：页面通过 `POST /api/requirements/exports` 发起同步导出，按任务查询进度，再从任务文件接口下载；发起与重试均检查 CSRF，任务进度和下载仅对发起人且当前仍有 `pm` 角色开放。原 `GET /api/requirements/export.xlsx` 保留为读取已有数据的兼容接口，不触发外部文档创建；新版页面使用上述同步导出流程。

## 飞书与环境配置

继续使用现有 `FEISHU_APP_ID`、`FEISHU_APP_SECRET`、`FEISHU_TENANT_KEY`。在部署机 `.env` 中新增：

```dotenv
FEISHU_REQUIREMENT_WIKI_SAMPLE_URL=https://zi4kl3ktexa.feishu.cn/wiki/GKOLwJnS1i8jDVk4HtecgszQn2l?create_from=create_doc_to_wiki
```

确认 `PUBLIC_APP_ORIGIN` 是相关人员可以访问的平台地址，当前部署使用：

```dotenv
PUBLIC_APP_ORIGIN=http://data.prt-ai.cn:8001
DEMO_MODE=false
```

配置写进 `.env`，不要直接作为 PowerShell 命令执行。更新的生产 Compose 已将 sample 配置传入容器。

无需额外的用户 Token、Webhook 或卡片回调地址。服务器需能访问 `open.feishu.cn:443`。演示模式不创建外部文档。

## Windows Docker 更新

同步最新完整源码到 `J:\PRT-demo-hub-test`，保留部署机原 `.env` 并添加上面的 sample 配置。特别注意同步新增的 `server/requirement-wiki.mjs`、`server/requirement-export.mjs`，以及修改后的 `compose.production.yaml`、`package.json`、`package-lock.json`。数据库结构由程序自动创建。

确保 Docker Desktop 正常、旧容器正在运行，然后执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File 'J:\PRT-demo-hub-test\scripts\update-docker.ps1' -ProjectDirectory 'J:\PRT-demo-hub-test'
```

脚本使用原数据卷备份、构建和重建容器。完成后按 `Ctrl+F5` 刷新浏览器，检查有不同截止日期、未设截止日期和已关闭需求的列表；再筛选需求并导出，核对列顺序、日期、关联人员和可点击的文档链接。

## 验收

1. 发布一条测试需求并上传需求文件，确认 sample 同目录出现独立文档，名称与需求一致，初始只有需求简述和需求文件下载链接。
2. 用负责人账号给当前需求上传 Demo 文件，保存数据概述、数据格式、成本预估、难度说明及注意事项。在需求详情等待同步完成，打开飞书文档，核对五项与平台一致。
3. 在飞书其他区块手动补充一段文字；回到平台修改 Demo 说明并保存，确认自动区域更新、人工文字保留。再补传需求文件、修改需求名称或转发给另一位员工，确认更新同一份文档、新负责人能编辑。绑定多个 Demo 或将一个 Demo 绑定多条需求时分别核对。
4. 用项目经理账号选择“进行中”并导出，选择范围中至少包含一条尚未创建文档的历史需求。等待页面进度完成，核对 sample 同目录补建文档、五项 Demo 说明、八列顺序、一条需求一行、缺失项为 `/`，点击标题、需求文档及单个／多个样例验证跳转。再次导出确认文档复用。换商务或普通员工确认无导出按钮。
5. 若失败，在需求详情或管理员设置查看具体错误。补齐接口权限、资源权限并发布应用版本后重试，无需再次发布同一需求。

本地测试使用模拟飞书服务；企业内真实创建、编辑授权及下载链接访问需部署后按以上步骤验收。
