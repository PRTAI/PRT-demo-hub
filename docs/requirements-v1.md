# PRT 数据样例管理平台｜第一版产品需求文档

- 文档版本：V1.0
- 日期：2026-09-03
- 状态：根据需求讨论形成的首版开发基线
- 当前交付：需求文档；不代表系统功能已实现

## 1. 产品目标

建设企业内部 Demo 管理平台，让员工上传文件、填写数据说明，由对应主管修改、审核并发布；主管上传免审核，产品经理可以查看全平台数据及状态。

平台重点保障文件与说明对应、版本可追溯、人员权限明确、审核流程完整。首版不建设完整的数据治理平台。

## 2. 用户明确要求

| 编号 | 要求 |
| --- | --- |
| U01 | Demo 主要为压缩包，同时兼容其他任意类型文件。 |
| U02 | 数据均为企业内部数据，首版不建设数据内容、来源或敏感性审核。 |
| U03 | 员工只能查看自己的数据；主管可以查看、修改、审核及发布其负责员工的数据；产品经理查看全部数据及状态。 |
| U04 | 员工上传由主管审核，主管上传免审核。 |
| U05 | 可见范围内的文件均可下载。 |
| U06 | 平台仅供企业内部使用。 |
| U07 | 用户规模在 100 人以内。 |
| U08 | 使用飞书登录；管理员分配平台角色与员工主管关系；文件先存储在服务器磁盘。 |
| U09 | 首版不迁移历史数据。 |
| U10 | 首版不建设额外的内部制度、保留期限等复杂配置。 |
| U11 | Demo 需要数据说明和版本管理；说明规范暂未最终确定，后续可能接入 LLM 自动生成说明。 |

## 3. 讨论中采用的首版默认规则

以下为此前需求方案中采用、随本版落盘的默认规则，与用户明确要求分开记录，方便后续调整。

1. 员工可查看自己的全部状态，包括草稿、待审核、已退回、已发布和已下架，并非只能查看已发布内容。
2. 每名员工配置一名直接主管；一名主管可负责多人，首版不沿组织层级递归扩展权限。
3. 产品经理默认只读及下载；管理员默认管理配置，不自动获得数据读取权限。账号可兼任多个角色。
4. 未分配角色的飞书用户进入待授权页，不能访问业务数据。
5. 员工未配置主管时可保存草稿，但不能提交审核。
6. 审核通过与发布合并为一个操作，不设置独立的待发布状态。
7. 同一 Demo 同时最多存在一个未完成版本（草稿、待审核或已退回）。
8. 版本号自动递增为 V1、V2、V3；同版本退回重提保留提交轮次。
9. 下架版本的历史说明和记录仍可见，但文件停止下载。这是“可见文件均可下载”的状态例外。
10. 主管变更时，员工数据的管理权限和未处理审核转移给新主管，历史记录不变。
11. 首版不自动解压、执行或解析任意文件，不要求在线预览。
12. 正常历史发布版本可下载；下架版本重新发布必须保留原因和操作记录，不允许员工自行恢复。

## 4. 建设范围

### 4.1 首版包含

- 飞书登录、平台用户关联、待授权页面、账号启停。
- 角色分配、员工主管关系维护和资产交接。
- Demo 创建、说明填写、多文件上传、草稿保存。
- 员工提交、撤回提交、主管退回、主管修改并审核发布。
- 主管上传直接发布。
- 文件与说明的版本管理、历史查看、基本差异展示。
- 基于归属人与主管关系的访问控制、文件下载。
- 下架、操作记录、下载记录。
- 我的 Demo、主管管理、产品经理全量视图及基础统计。
- 业务分类及上传限制配置。
- 本地磁盘文件存储及数据库、文件配套备份。

### 4.2 首版不包含

- 历史迁移、外部公开访问和公开分享链接。
- 数据来源、敏感内容、脱敏及业务质量自动检测。
- 飞书组织架构自动同步和复杂多级组织权限。
- 多级审批、通用工作流设计器、逐次下载审批。
- 任意文件在线预览、压缩包内容对比、代码或 SQL 执行环境。
- LLM 实际调用、自动生成说明和智能检索。
- 完整说明表单设计器、复杂数据治理与保留制度配置。
- 飞书消息通知。首版使用站内待办和状态提示。

## 5. 角色和权限

| 能力 | 员工 | 主管 | 产品经理 | 管理员 |
| --- | --- | --- | --- | --- |
| 上传自己的 Demo | 是 | 是 | 需兼任员工或主管 | 需兼任员工或主管 |
| 查看数据及全部状态 | 自己 | 自己和直接负责的员工 | 全部 | 无默认业务读取权限 |
| 下载文件 | 可访问文件 | 可访问文件 | 可访问文件 | 由兼任角色决定 |
| 修改未发布内容 | 自己的草稿、退回内容 | 自己及下属的未发布内容 | 否 | 否 |
| 修改已发布内容 | 创建新版本后提交 | 创建新版本后发布 | 否 | 否 |
| 提交审核 | 自己 | 自己无需审核 | 否 | 否 |
| 审核并发布员工版本 | 否 | 仅负责范围 | 否 | 否 |
| 直接发布自己的版本 | 否 | 是 | 否 | 否 |
| 下架版本 | 否 | 自己及下属 | 否 | 否 |
| 全局数据和状态统计 | 否 | 否 | 是 | 由兼任角色决定 |
| 角色、主管关系、账号启停 | 否 | 否 | 否 | 是 |
| 资产交接、基础配置 | 否 | 否 | 否 | 是 |

权限原则：

- 平台账号必须属于允许使用的企业范围，飞书登录成功本身不等于获得业务权限。
- 所有页面、接口、下载请求均执行相同的后端权限规则。
- 产品经理只能读取，不能因为看得到而编辑或审核。
- 主管可以修订下属提交并直接发布，不要求额外第二级审核。
- 是否免审核依据实际操作者当前主管角色及其资源管理范围，不依据文件上传人字段或可修改的归属字段。
- 多角色权限合并，但账号停用、下架下载限制等约束仍生效。
- 人员关系和角色变更后，后续请求应使用最新权限，旧链接不能绕过校验。

## 6. 飞书登录和人员管理

### 6.1 登录流程

1. 用户点击飞书登录并完成授权。
2. 平台验证身份结果并使用稳定的飞书用户标识关联本地用户。
3. 使用授权范围内可获得的姓名、头像展示身份，不以姓名作为账号唯一标识。
4. 已启用且已分配角色的用户进入工作台；未分配角色进入待授权页；停用用户不能进入业务页面。
5. 平台会话与账号启停、角色调整配合，不能只在首次登录时检查权限。

组织关系全部由管理员在平台配置，不依赖获取飞书部门通讯录。首版无需为了 Demo 填写收集私人联系方式。

### 6.2 自动填写

| 字段 | 规则 |
| --- | --- |
| 创建人 | 实际创建用户，系统记录，不可手动修改。 |
| 归属人 | 新建默认本人，员工不可自行修改；交接由管理员处理。 |
| 版本提交人 | 实际提交者，系统记录。 |
| 修改人 | 实际修改者，按操作记录。 |
| 审核、发布人 | 实际处理者，系统记录。 |
| 负责主管 | 根据当前平台人员关系展示；审核发生时另存快照。 |

### 6.3 管理操作

- 用户列表、角色配置、员工主管配置、无主管员工筛选。
- 账号启用和停用。
- 员工换主管时转移当前管理权限和待审核事项，记录变更前后关系。
- 管理员转交资产时记录原归属人、新归属人和原因；旧归属员工失去访问权限，新归属员工获得权限。
- 资产归属变化不改写创建、提交、审核等历史署名。
- 首位管理员的初始化方式属于部署配置，不向所有首次登录者开放管理员权限。

## 7. Demo 和数据说明

### 7.1 对象结构

一个 Demo 资产拥有多个版本；每个版本绑定一份说明和一组文件。资产归属决定访问范围，实际操作人用于追溯责任。

### 7.2 首版表单

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| Demo 名称 | 是 | 人工填写。 |
| 简介 | 是 | 简述内容和用途。 |
| 业务分类 | 是 | 从管理员维护的分类选择。 |
| 标签 | 否 | 用于检索。 |
| 归属人 | 自动 | 默认当前用户，管理员交接时调整。 |
| 创建人 | 自动 | 记录实际创建者。 |
| 负责主管 | 自动 | 按平台关系展示。 |
| 数据内容说明 | 是 | 描述压缩包或文件包含什么。 |
| 使用方法 | 是 | 如何打开、导入或使用。 |
| 注意事项 | 否 | 环境依赖或其他提示。 |
| 本次变更说明 | 后续版本必填 | 描述相对上一版本的变化。 |
| 文件清单 | 自动 | 由版本文件生成。 |

采用固定表单和填写示例，字段结构化保存。业务说明随版本保存，历史版本显示当时的说明。技术上保留说明结构版本标识，方便未来演进，不建设复杂规范管理界面。

## 8. 文件上传、存储和下载

- 支持 ZIP、RAR、7Z 及其他任意扩展名，不以文件类型白名单限制业务上传。
- 单版本支持多文件、拖拽上传、进度和失败重试；下载至少支持单文件。
- 文件大小、单版本总大小、文件数量限制可配置，数值在部署阶段确定。
- 草稿可新增、删除、替换文件；待审核内容不可由员工直接修改。
- 文件先写临时区域，完整写入并校验成功后才能关联为有效版本文件。
- 内部保存使用唯一标识，不用原始文件名拼接磁盘路径；下载时保留原文件名。
- 文件目录独立于应用程序和公开 Web 目录，不能直接静态公开。
- 文件名、路径和响应处理必须避免路径穿越、覆盖系统文件以及上传内容作为网页执行。
- 任意格式支持指保存和下载，不代表自动解压、解析、预览或执行。
- 文件下载前校验当前用户、资源权限、文件所属版本和版本状态。
- 正常可访问的草稿、待审核、退回和历史发布文件均可下载；下架版本禁用下载。
- 显示文件名称、大小、上传人、时间和所属版本；保存校验值用于完整性和替换识别。
- 临时文件定期清理；磁盘不足需显式失败，不留下可提交的半成品。
- 文件复用不得导致删除草稿文件时误删仍被历史版本引用的文件。

## 9. 业务流程

### 9.1 员工提交

创建 Demo → 上传文件、填写说明 → 保存草稿 → 校验必填项及主管 → 提交审核。

提交时形成内容快照并记录提交轮次。员工可撤回待审核提交，恢复草稿后编辑；不能在主管审核对象上静默覆盖文件。

### 9.2 主管处理员工 Demo

查看待审核 → 阅读说明、下载文件、查看变更 → 选择退回，或修改并审核通过发布。

- 退回必须填写意见。
- 允许主管修改文字和文件后直接发布。
- 保留员工原始提交快照、主管修订和最终发布内容。
- 修改不改变 Demo 归属人。
- 审核通过与发布原子完成，不出现审核对象和发布对象不一致的状态。

### 9.3 主管上传

创建 Demo → 上传文件、填写说明 → 保存草稿或直接发布。

不进入人工审核，但必须满足文件完整性、必填项和权限要求。记录直接发布操作以及主管免审核依据，不伪造一条人工审核通过记录。

### 9.4 更新和下架

- 已发布内容更新必须创建新版本。
- 员工新版本交主管审核；主管在负责范围内创建或修订新版本可直接发布。
- 新版待审核不影响旧发布版本；新版发布成功后切换默认发布版本。
- 主管可下架自己及下属的版本，填写原因，记录处理人和时间。
- 默认版本下架后，不自动把可能不适用的旧版作为默认版本；由主管明确选择仍已发布的版本，否则显示暂无可用发布版本。
- 下架无法收回已下载到设备的文件，平台保留下载记录供排查。

## 10. 状态和版本规则

| 当前状态 | 操作 | 操作角色 | 结果 |
| --- | --- | --- | --- |
| 草稿 | 保存 | 归属员工或有管理权限主管 | 草稿 |
| 草稿 | 提交审核 | 归属员工且已配置主管 | 待审核 |
| 草稿 | 直接发布 | 有管理权限主管 | 已发布 |
| 待审核 | 撤回 | 提交员工 | 草稿 |
| 待审核 | 退回并填写意见 | 负责主管 | 已退回 |
| 待审核 | 修改并审核发布 | 负责主管 | 已发布 |
| 已退回 | 修订并重提 | 归属员工 | 待审核 |
| 已退回 | 修订并发布 | 负责主管 | 已发布 |
| 已发布 | 创建新版本 | 归属员工或有管理权限主管 | 原版本不变，新版本为草稿 |
| 已发布 | 下架并填写原因 | 有管理权限主管 | 已下架 |
| 已下架 | 恢复发布并填写原因 | 有管理权限主管 | 已发布，内容不变 |

- 已发布、已下架的版本内容不可原地更改。
- 版本号按资产自动递增，不能重复；删除草稿后不复用已分配编号。
- 同一资产同时最多有一个未完成版本。
- 退回重提不增加版本号，但新增提交轮次及审核记录。
- 一个资产可以同时有 V2 已发布、V3 待审核，列表必须同时呈现。
- 版本差异仅比较文件新增、删除、替换及说明字段变化，不比较压缩包内部内容。
- 首版无需独立资产生命周期状态机，以当前发布版本和未完成版本概括状态。

## 11. 删除与留痕

- 员工可以删除自己的、从未提交过的草稿；主管可在管理范围内处理同类草稿。
- 曾提交、审核或发布的版本不直接物理删除；保留版本及处理记录。
- 已发布内容用下架控制后续下载。
- 删除版本文件引用与实际磁盘回收分开处理，避免破坏其他版本。
- 普通业务操作不得修改历史审核及审计记录。

## 13. 概念数据对象

以下为逻辑对象，不限定技术栈或实际数据库拆表方式。

| 对象 | 主要信息 |
| --- | --- |
| 平台用户 | 内部用户 ID、飞书稳定身份标识、姓名、头像、启停状态。 |
| 用户角色 | 用户、角色；支持多角色。 |
| 主管关系 | 员工、当前主管、变更记录。 |
| Demo 资产 | ID、归属人、创建人、当前发布版本、创建时间。 |
| Demo 版本 | 资产 ID、版本号、状态、说明、分类标签、变更说明、结构版本标识。 |
| 版本文件关联 | 版本、文件、展示文件名。 |
| 文件对象 | 存储标识、大小、校验值、上传者、时间、完整性状态。 |
| 提交与审核 | 提交轮次、原始内容快照、主管修订、审核意见、处理人及时间。 |
| 操作与下载事件 | 操作者、动作、对象、结果、时间、必要变更内容。 |
| 基础配置 | 分类、上传大小、数量限制。 |

历史记录保留操作时的人员展示信息快照，同时关联稳定用户 ID。当前姓名变化不应破坏历史关联。

## 14. 基础运行与异常要求

- 上传、提交、审核及发布支持重复请求保护，不能因双击产生重复版本或重复发布。
- 多人编辑时检测冲突，避免静默覆盖；撤回和发布同时发生时只允许合法的一项成功。
- 发布时保证版本状态、文件和默认发布指向一致；发布失败时原发布版本不受影响。
- 页面退出或网络异常时已保存草稿可继续处理；未上传完整文件不能提交。
- 管理员更改主管或角色时，正在打开的页面不能继续使用已失效权限完成操作。
- 备份必须覆盖数据库和文件，并能够恢复其对应关系。
- 监测磁盘空间、上传失败、应用错误和备份结果。
- 文件大小、磁盘容量、备份周期、恢复目标、具体性能指标需结合部署资源确定，不预先作未经验证的承诺。

## 15. LLM 扩展预留

后续可增加：上传 → 解析支持内容 → 按规范生成说明草稿 → 人工确认 → 主管审核。

首版仅保留结构化说明、说明结构版本、稳定文件和版本关联。未来模型输出不能直接发布或覆盖人工修改；不支持的格式和生成失败必须允许人工填写。是否支持压缩包解析、模型服务及可发送数据范围在引入 LLM 时单独确定。

## 17. 开发阶段需要确定的配置

以下不阻碍需求落盘，在实现和部署时确定：

- 前后端框架、数据库与部署方式。
- 飞书应用配置、允许登录的企业范围、回调地址和授权字段。
- 首位管理员初始化与后续管理员管理方式。
- 服务器文件目录、容量、上传大小及数量限制。
- 备份位置、周期和恢复目标。
- 初始用户角色、员工主管关系和业务分类。

建议开发顺序：身份与权限 → 资产、说明及上传 → 版本与审核发布 → 列表检索、产品经理视图 → 操作记录、备份与验收。
