## 快速上手

| 顺序 | 操作人 | 操作 | 完成标志 |
| --- | --- | --- | --- |
| 1 | 产品经理或商务 | 在“需求中心”发布业务需求。 | 需求详情显示“进行中”。 |
| 2 | 被指定的员工或主管 | 查看需求并下载文档，然后在需求详情点击“上传 Demo”（当前需求默认选中），或从“我的 Demo”上传后选择需求。 | 保存后进入 Demo 详情，文件已保存，关联需求正确。 |
| 3 | 员工 | 点击“提交主管审核”，选择本次审核主管。 | 版本状态变为“待审核”。 |
| 4 | 审核主管或有管理权限的人员 | 检查文件、说明和需求，审核通过后发布；主管自己的 Demo 可直接发布。 | 版本状态变为“已发布”。 |
| 5 | 产品经理和对应商务 | 接收飞书消息，点击消息中的应用入口。 | 打开对应 Demo 详情。 |

草稿可以暂不绑定需求；提交审核、直接发布和恢复发布前，必须至少绑定一个需求。仅发布需求本身不会触发 Demo 发布通知。

## 登录与角色

1. 接入能够访问部署主机的公司内网或 VPN。
2. 打开管理员提供的统一访问地址。当前 Windows Docker 测试地址为 `http://192.168.110.25:8001`；以实际部署配置为准。
3. 点击“使用飞书账号登录”，按飞书提示完成企业身份登录。
4. 如果显示“身份已确认，等待分配权限”，将页面上的“平台用户编号”提供给平台管理员，分配完成后点击“刷新权限”。

| 角色 | 主要操作 |
| --- | --- |
| 员工 | 准备自己的 Demo、上传文件、编辑草稿、提交审核，以及访问获得授权的 Demo。 |
| 主管 | 新建自己的 Demo，审核本次指定由自己负责的 Demo，管理有管理权限的版本；将自己可见的需求转发给员工。 |
| 产品经理 | 发布需求、转发给主管或员工，全量查看和下载 Demo，并管理工作版本、发布及授权。 |
| 商务 | 发布需求、转发给主管或员工，绑定自己需求的可见 Demo、全量查看和下载允许展示的 Demo 内容。 |
| 管理员 | 配置人员角色与主管、交接资产、维护平台参数、备份和查看飞书通知记录。 |

角色可以叠加。新建全新 Demo 的入口仅向员工和主管开放；产品经理或商务需要承担这项工作时，由管理员额外分配相应角色。只有管理员角色不会自动获得 Demo 文件和说明的访问权限。

仅商务角色默认不能编辑 Demo 内容，且不展示成本预估、注意事项、版本差异和操作记录等受限内容。对单个 Demo 的明确授权及叠加角色以实际权限为准。

## 发布和管理需求

### 发布需求

产品经理或商务进入侧栏“需求中心”，点击“发布需求”，填写需求标题、业务分类和需求内容，再点击“发布需求”。标题和需求内容必填，分类可选。

“指定查看人员”为可选项，可选择多位已启用的平台成员；“需求文档”同样可选，支持一次选择多个文件，例如 Word、PDF、Excel、PPT 或文本。选择完成后点击“发布需求”或“保存修改”才会上传文档，单文件大小沿用平台配置限制。文档作为附件保存，不自动解析为需求正文，正文可填写简要背景和验收要求。原发布人可在详情点击“编辑需求 / 上传文档”继续补充附件。

将一个或多个需求文档拖入上传区域，松开鼠标即可加入待上传列表；也可以点击该区域，在 Windows 中按住 `Ctrl` 或 `Shift` 多选。支持拖入与点击混用、分次累加，不会覆盖先前选择。列表逐项显示名称与大小，可移除误选文档；取消文件选择窗口会保留原列表，重复选择同一文件会自动去重。文件夹会跳过并提示选择具体文件。点击“发布需求”或“保存修改”时才上传文档。

若提示部分文档上传失败，需求内容和已上传文档会保留，再次保存可重试剩余文档。成功后在需求详情的“需求文档”区域点击文件名即可下载。

平台沿用“产品经理（pm）”角色对应需求管理人员。产品经理和商务可查看全部需求；其他角色（包括单独的管理员、主管和员工）只可查看指定给自己的需求及详情并下载文档。指定人员不能在需求中心发布、编辑、上传文档、关闭或改变 Demo 绑定；主管另可通过“转发需求”追加员工。未指定任何人员的需求，仅产品经理和商务可在需求中心查看；历史需求可由原发布人补选人员，或由产品经理、商务转发追加人员。取消指定后，详情与下载权限立即收回。

需求内容建议写清楚以下信息：

- 业务背景和面向的客户或使用场景。
- 需要展示的分析目标、数据字段或文件类型。
- Demo 的验收标准，以及准备数据时需要遵守的约束。

示例：准备零售门店销售分析 Demo，包含日期、门店、商品、销售额等合成字段，能够演示门店对比与销售趋势，并附带字段说明。

### 转发需求给多人

1. 从“需求中心”或“我的需求”打开需求详情，点击“转发需求”。
2. 搜索人员姓名并多选接收人，产品经理和商务可按主管、员工筛选；主管只能选择员工。已关联人员显示“已关联”，无需重复转发。
3. 点击“确认转发”，详情的“关联人员”自动追加接收人。接收人可以在自己的“我的需求”中打开详情并下载文档。

产品经理和商务可以转发他人发布的需求。主管只能转发自己有权查看的需求，当前可以转发给全部已启用员工，不限制为自己的下属；兼任主管的人员不在普通主管的接收范围内。兼任产品经理或商务时按合并权限处理。单独的员工、管理员没有转发入口。

转发保留原有关联人员，每条需求最多关联 100 人；不会改变需求状态、正文、发布人或 Demo 权限。只需要查看附件的员工不会因此获得其他员工 Demo 的访问权。若提示内容已更新，点击“刷新人员”后重新提交。

### 查询、修改和关闭需求

在需求中心可按标题、内容、分类或发布人搜索，也可筛选“进行中”“待更新”“已交付”“已关闭”。状态下拉菜单使用平滑动画；列表中的 Demo 数量只统计当前账号有权查看的 Demo。侧栏“我的需求”只显示指定给当前账号的需求。

打开需求详情后，原发布人可点击“编辑需求”“关闭需求”或“重新开启”。原发布人仍需保有产品经理或商务角色。关闭会停止接受新的 Demo 绑定，已有绑定保留，对应商务仍可收到这些 Demo 后续的发布通知。

### 从需求关联 Demo

| 场景 | 操作 |
| --- | --- |
| 为需求准备新的 Demo | 被指定的员工或主管在需求详情点击“上传 Demo”（自动关联当前需求），或从“我的 Demo”或“数据工作台”上传后在“关联需求”中勾选需求。 |
| 关联已有 Demo | 原需求发布人在详情点击“绑定已有 Demo”，搜索并选择目标。 |
| 在 Demo 中选择需求 | 编辑 Demo，在“关联需求”区域搜索并勾选，可选择多个。 |
| 从 Demo 查看业务背景 | 在 Demo 详情的“关联需求”区域点击需求标题。 |
| 从需求查看成果 | 在需求详情的“关联 Demo”区域点击对应 Demo。 |

一个需求可对应多个 Demo，一个 Demo 最多关联 20 个需求；绑定关系由整个 Demo 共用，不按版本分别设置。

需求发布人可在需求中心绑定自己有权查看的 Demo；Demo 编辑者可在 Demo 编辑页选择需求。指定人员在需求中心仅有查看权限。绑定不会增加 Demo 文件或说明的访问权限。待审核或含已发布版本的 Demo 不能解除最后一个需求；需要调整时，先绑定新的需求，再解除原关系。

历史 Demo 可以逐步补绑。历史已发布版本继续可用，下一次提交、发布或恢复发布前需完成绑定；历史待审核 Demo 可由需求发布人在需求中心先补绑。

## 上传和编辑 Demo

1. 在“我的 Demo”“数据工作台”等页面点击“上传 Demo”。员工或主管也可从需求详情点击“上传 Demo”，打开的编辑界面会默认关联当前需求。
2. 填写名称、业务分类、简介，按需填写标签。
3. 在“关联需求”中勾选对应业务需求。
4. 拖入文件或点击上传按钮选择文件。
5. 填写数据说明、成本预估和难度说明。
6. 点击“保存 Demo”，等待文件上传和校验完成，确认详情页已显示保存的内容。

草稿允许先保存部分信息。提交审核或发布时，系统会检查：

| 检查项 | 要求 |
| --- | --- |
| 名称、简介 | 不能为空。 |
| 业务分类 | 必须是管理员当前配置中的有效分类。 |
| 数据说明、成本预估、难度说明 | 必须填写。编辑页中的成本和难度可在保存草稿时留空，但提交或发布时必填。 |
| 变更说明 | V2 及以后版本必须填写“本次变更说明”。 |
| 文件 | 至少一个完整、非空文件，且符合当前大小和数量限制。 |
| 关联需求 | 至少一个。 |

Demo 文件和压缩包不设置单文件大小及单版本总大小限制，文件夹请先打包后上传。默认每个版本最多 20 个文件，文件数量以上传页面显示的实际配置为准。旧设置中的单文件及版本总大小数值不再限制 Demo，需求文档仍沿用单文件大小设置。实际可上传容量取决于服务器可用磁盘空间；使用反向代理时还需确认代理允许大文件请求。选择文件后，需点击“保存 Demo”才会完成上传；界面显示“等待上传”表示文件还未保存。

如果保存部分成功后提示某个文件失败，已保存的内容仍会保留，可按提示继续处理未完成文件。如果提示“内容已被更新”，先复制尚未保存的说明，再点击“加载最新版本”，核对最新内容及需求绑定后重新编辑。

## 使用 AI 生成数据说明

数据说明和智能检索统一使用 DeepSeek 官方高级模型 `deepseek-v4-pro`，由管理员按 [统一模型配置说明](deepseek-configuration.md)填写官方 Key。默认关闭思考模式以减少等待和额度截断。

1. 先保存 Demo 和文件。
2. 在 Demo 详情点击“编辑内容”。
3. 在“数据说明”区域点击“AI 生成”。
4. 等待后台任务完成；可以继续填写其他字段或保存草稿，重新进入编辑页后可以查看任务状态或结果。
5. 阅读“AI 数据说明待审查”，核对文件结构、字段含义和使用场景。
6. 点击“应用到数据说明”，确认内容后再点击“保存 Demo”；不采用时点击“暂不采用”。

生成结果不会自动覆盖数据说明，也不会代填发布所需的全部字段。成本预估和难度说明仍需根据实际情况填写。任务完成后按现有飞书通知配置提醒发起人。

如果生成失败，页面会显示错误，可重新发起。服务重启会中断正在运行的生成任务，需要重试。持续超时或提示 401、403、404 时，由运维按[宿主机部署说明中的 AI 排查步骤](host-deployment.md#ai-数据说明配置与排查)检查模型、协议、地址、权限和网络。

## 提交审核与发布

### 员工提交审核

在草稿或退回版本中，先完成所有检查项，再点击“提交主管审核”，选择本次审核主管并确认。提交后版本变为“待审核”，指定主管收到飞书提醒。

普通员工无法直接修改待审核版本。需要修改时，可以“撤回提交”，或由主管“退回修改”；修改并保存后重新提交。

### 审核主管处理

1. 进入“待我审核”，打开目标 Demo。
2. 对照关联需求检查文件、数据说明、成本与难度。
3. 需要补充时点击“退回修改”，填写原因；归属员工会收到返修通知。
4. 内容满足要求时，必要的修改先保存，再点击审核发布操作并确认。
5. 如需通知自动接收人之外的人员，在确认区域勾选“额外抄送人员”。

主管自己准备的 Demo，以及有管理权限人员负责的工作版本，可以直接发布。审核通过发布与直接发布适用相同的需求绑定和内容完整性检查。

### 状态说明

| 状态 | 含义与下一步 |
| --- | --- |
| 草稿 | 可继续补充文件、说明和需求，然后提交或发布。 |
| 待审核 | 等待本次审核主管处理；员工可撤回。 |
| 已退回 | 根据主管意见修改，再提交审核。 |
| 已发布 | 可正常查看和使用；修改内容需要创建新版本。 |
| 已下架 | 文件停止下载和预览；有管理权限人员可填写原因后恢复发布。 |

发布完成后，产品经理和对应商务会自动收到飞书通知，无需逐个手动勾选。

## 查看、下载与版本维护

### 查找和使用 Demo

在数据资产库或数据工作台中，可按关键词、业务分类、归属人、更新时间和版本状态筛选。也可以进入“智能检索”，用业务场景或字段描述查找，例如“适合演示门店销售趋势的数据”。

检索只返回当前账号有权限查看的内容。智能检索中点击结果可进入 Demo 详情；如果模型不可用，页面可能展示本地检索结果。

Demo 详情的“文件清单”中可查看文件名和大小，并使用“预览”或“下载”。ZIP 支持浏览目录和预览支持的包内文件；图片、文本、音视频的预览受文件格式和浏览器能力影响。RAR、7z 和加密压缩包等不支持直接展开时，可下载后使用本机工具。

商务账号可通过版本选择器查看允许展示的内容；不展示受限的版本差异和操作记录。下架版本的文件不能下载或预览。

### 更新与下架

- 更新已发布内容：在已发布版本点击“创建新版本”，修改文件和说明，填写变更说明，再按流程发布。存在未完成的工作版本时，先处理该版本。
- 对比版本：有相应权限的账号进入“版本与差异”，查看说明和文件变化。
- 查看过程：进入“操作记录”，查看上传、编辑、审核、发布和需求绑定等记录。
- 停止使用：有管理权限人员点击下架操作并填写原因；恢复时同样需要原因，并重新检查发布条件。
- 切换默认版本：在正常已发布版本中执行设为默认版本操作。

新版本尚未发布时，原已发布版本仍可使用。创建新版本沿用整个 Demo 的需求绑定。只有从未提交过的草稿可以删除，确认前请检查是否还有需要保留的内容。

## 飞书通知规则

| 业务动作 | 自动通知对象 |
| --- | --- |
| 提交审核、撤回提交 | 本次指定的审核主管。 |
| 退回修改 | Demo 归属员工，并附处理原因。 |
| 审核通过发布、直接发布、恢复发布 | 全部已启用产品经理、关联需求的商务发布人，以及按原规则接收通知的 Demo 归属员工。发布时还会通知手动额外抄送人员。 |
| 下架、设为默认版本 | Demo 归属员工和已启用产品经理，排除本次操作人。 |
| AI 数据说明生成完成 | 本次任务发起人。 |

“对应商务”按关联需求的发布人确定，且发送时仍须具有商务角色。产品经理发布的需求不会自动指定其他商务。多条需求对应不同商务时全部通知；同一商务发布多条关联需求、同时是产品经理或被手动抄送，只接收一条该次通知。

产品经理和对应商务即使是本次发布或恢复发布的操作人，也会收到自动通知。归属员工是操作人时按原规则排除；如果同时属于产品经理或对应商务，仍会收到自动通知。

发布通知包含 Demo 名称、版本、归属员工、发布时的需求标题和飞书应用入口，不发送原始文件或成本等说明字段。通知队列约每 5 秒处理一次，实际送达取决于网络和飞书响应；失败最多尝试 5 次。账号停用、角色移除、商务对应需求已解绑或版本状态不再适用时，任务可能被取消。

发布需求、保存草稿、修改需求和添加绑定不会触发 Demo 发布通知。历史已发布数据不会补发消息；本地体验环境不会实际发送飞书消息。

## 管理员操作

### 人员与权限

用户首次登录后，进入“人员与权限”，按姓名搜索并点击“配置”，选择角色、负责主管及账号启用状态，再保存。

单个 Demo 的协作权限由具有授权权限的人员在 Demo 详情“权限设置”中配置：只读可查看和下载，上传可维护工作版本的说明和文件，管理可执行审核发布等操作。实际按钮还受角色和版本状态约束。

人员调岗或离职时，先在“资产交接”中筛选和选择 Demo，指定已启用的新归属人，填写交接原因并确认；如原人员负责下属，再调整员工主管，最后停用原账号。管理员可在停用后删除账号，删除保留历史创建人、操作署名、Demo、需求和文件引用，并可从“已删除”筛选中恢复账号。历史创建人和操作署名会保留。

### 平台设置与备份

进入“平台设置”，可维护业务分类、文件大小与数量限制，并查看存储、运行配置和备份状态。调整分类后，历史草稿如果使用已移除分类，下一次提交或发布前需重新选择。

点击“立即备份”，等待任务和完整性校验完成。备份包含数据库、文件、需求和绑定关系，备份中清除登录会话；请由运维将完成的备份另存到独立存储。

### 查看飞书发送记录

进入“平台设置 → 飞书通知”，点击“刷新发送记录”。

| 状态 | 处理方式 |
| --- | --- |
| 等待发送 / 重试 | 等待后台队列处理，再刷新。 |
| 发送成功 | 飞书接口已接受消息；接收人可检查对应应用机器人会话。 |
| 发送失败 | 查看错误，修复应用凭据、权限、可用范围或网络后点击“重试”。 |
| 已取消 | 检查版本状态、账号角色和需求绑定；历史事件不自动重新补发。 |

页面显示最近 100 条记录。飞书应用需要启用机器人、具备 `im:message:send_as_bot` 权限，且应用可用范围包含实际接收人；飞书配置变更需按控制台要求发布生效。

## 常见问题

| 现象 | 处理方法 |
| --- | --- |
| 访问不了平台 | 确认公司网络或 VPN、访问地址、部署主机开机状态和服务健康状态。 |
| 飞书登录后一直等待授权 | 联系管理员分配平台角色，再点击“刷新权限”。 |
| 看不到“发布需求” | 确认账号具有产品经理或商务角色。 |
| 看不到“上传 Demo” | 确认账号具有员工或主管角色；需求详情中的上传入口仅在需求进行中时显示。 |
| 提示先绑定需求 | 编辑 Demo 勾选至少一个需求；待审核版本也可由需求发布人在需求中心绑定。 |
| 需求搜不到或无法新增绑定 | 检查需求是否已关闭；新增绑定只支持进行中的需求。 |
| 最后一个需求无法解绑 | 待审核或含已发布版本的 Demo 必须保留一个需求，先添加替代需求。 |
| 发布提示缺少成本或难度 | 保存草稿可暂空，但发布时需填写成本预估和难度说明。 |
| AI 生成按钮不可用 | 先保存 Demo 和至少一个文件，再进入编辑页；已有任务时等待完成。 |
| AI 超时或服务重启中断 | 查看错误后重新发起，持续失败交由运维自检模型配置。 |
| 提示内容或绑定被别人更新 | 保留未保存内容，加载最新版本，再核对并重新编辑。 |
| 商务未收到发布通知 | 确认其是关联需求的发布人、仍有商务角色、账号启用、发送前未解绑，再检查管理员通知记录及飞书应用范围。 |
| 已发布但通知失败 | 发布结果保留，由管理员修复发送配置并重试通知，无需重复发布。 |
| 更新后页面没有需求中心 | 强制刷新或重新登录；让运维确认前端已重新构建、后端已重启且使用了完整的新代码。 |

## 部署更新与验收

当前 Windows Docker 实例位于 `J:\PRT-demo-hub-test`，容器为 `prt-datahub-production`，使用原有数据卷；按 [Windows Docker 简明部署手册](windows-docker-guide.md#更新当前已运行的容器并保留旧数据)更新。无需手动执行 npm 或 SQL，更新前备份并保留 `.env`。其他采用 Windows 宿主机 Node.js 服务的实例见[宿主机部署说明](host-deployment.md#版本更新)。

如果改在新目录启用一套空数据环境，按[Windows 新目录全新部署](fresh-windows-deployment.md)操作；该流程针对 `192.168.110.25:8081`，包含独立配置、内网访问、飞书地址变更和新管理员初始化。

如已找到 `D:\PRT-demo-hub` 中的原数据并需要保留，按[恢复旧数据并更新部署](restore-windows-deployment.md)操作，沿用原飞书应用及账号权限。

部署后按以下流程验收，使用明确标注的合成业务数据，发布时会真实通知符合规则的接收人：

1. 从统一入口完成飞书登录，确认已有人员、Demo 和文件仍可访问。
2. 用商务账号发布需求，上传文档并指定一位员工；确认产品经理及该员工可查看并下载，其他员工无法查看。另发一条不指定人员的需求，确认可以成功发布。
3. 被指定员工从需求详情点击“上传 Demo”，确认当前需求已默认选中，上传小文件并保存；需求详情中该员工不能编辑、上传文档、关闭或改动绑定。
4. 检查未绑定草稿可以保存，而未绑定的完整 Demo 不能提交或发布。
5. 完成说明、成本、难度和绑定后，提交指定主管审核并发布。
6. 确认产品经理和该需求的商务发布人收到消息，点击消息可打开 Demo。
7. 由管理员查看通知记录，检查同一接收人没有因多条需求或多个角色收到重复通知。
8. 用一份小 CSV 验证 AI 生成、审查应用和保存，确认成本、难度等字段仍符合发布要求。

首次启动会自动创建需求、绑定、指定人员及需求文档关联表，无需手动执行 SQL。健康检查通过只说明基础服务可用，仍需完成页面操作和真实飞书送达验收。
