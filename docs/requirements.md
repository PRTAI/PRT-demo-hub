# 需求中心与 Demo 绑定

## 使用流程

1. 产品经理或商务进入侧栏“需求中心”，填写标题、需求内容及可选业务分类，可选择多位指定查看人员、上传一个或多个需求文档，再点击“发布需求”。人员和文档均非必填，正文建议说明业务背景、演示场景、所需数据及验收标准，附件不会自动解析为正文。需求状态支持“进行中”“待更新”“已交付”“已关闭”，只有产品经理或商务可以修改状态。
2. 被指定的员工或主管可查看需求及下载文档，在需求详情点击“上传 Demo”即可打开数据工作台上传界面，当前需求会默认选中；也可以从“我的 Demo”上传后手动选择需求。侧栏“我的需求”集中显示指定给当前账号的需求。员工只读；被直接指定的主管还可转发给多位员工。
3. 关联需求为可选项。独立上传新 Demo 时留空，首次保存会自动创建一张需求卡片并关联；已选择需求时只关联所选需求。后续仍可解除最后一个关联，不影响提交主管审核、直接发布及恢复发布。成本预估与数据量级在保存时选填，提交审核、直接发布或恢复发布时必填；分别以两周时间和两周产量为参考，后端同步校验。
4. 需求详情展示当前用户有权查看的关联 Demo，可以跳转 Demo 详情；Demo 详情展示关联需求，可以反向跳转。
5. 原需求发布人可在需求详情中“绑定已有 Demo”；Demo 自动创建的需求允许项目经理或商务管理。只允许选择自己有权查看的 Demo。Demo 编辑者在 Demo 编辑页选择关联需求。

## 独立上传自动创建需求

员工或主管上传新 Demo，不选择关联需求，必须填写非空的 Demo 名称并选择至少一个非空文件或压缩包才能保存；其他说明字段可以后补。首个文件完整上传并保存成功后，自动创建一张“进行中”需求卡片。标题、内容和业务分类分别取 Demo 名称、简介和分类；简介为空时使用名称。发布日期为保存当天（北京时间），截止日期留空。上传人记为发布人和研发负责人，商务负责人暂空，因此可在“我的需求”中看到卡片。

这类自动创建的需求允许所有项目经理、商务编辑，补充需求文档、调整负责人及管理 Demo 关联。只有员工或主管角色的上传人保持需求只读权限，主管仍可按原规则转发。手动发布的需求继续由具有项目经理或商务角色的原发布人管理。

文件落库、卡片及关联在同一事务中提交，后端同时检查名称和实际文件是否完整。仅保存说明、上传空文件或首个文件上传失败／中断时不创建卡片和发布任务，可继续重试；首个文件已经成功、后续文件失败时保留已完成部分。重复保存、以后编辑说明、上传文件或创建新版本都不会重复建卡。标题与简介是首次保存时的初始值，后续可在需求详情编辑。

如果移除了全部 Demo 文件、删除草稿或解除了最后一个 Demo 关联，尚未被维护的自动卡片不再出现在需求中心、我的需求、搜索和 Excel 导出中，也暂停发送需求发布通知。后台保留原记录及仍存在的绑定；在原 Demo 补传文件后恢复同一张卡片。旧版本留下的同类空卡片更新后也按此规则处理。已编辑需求、调整负责人／状态、补充需求文档或有回复的需求，以及正常手动发布的需求，继续保留自己的生命周期，不随 Demo 删除而隐藏。

自动卡片保留需求发布通知，飞书文档在项目经理首次导出成功后开始同步，初始不创建飞书日程。项目经理或商务修改需求正文、补充具体需求内容，或上传需求文档后，才创建日程；单纯改标题、负责人、状态、Demo 说明或上传更多 Demo 文件不会提前创建。重新开启已关闭需求时，按明确填写的新日期发布日程。更新会清理旧版本为尚未补充内容的自动卡片提前创建的日程；已有需求、Demo 和文件保留。此功能无需新增 `.env`，不会为历史 Demo 批量补建卡片。

## 权限与关系

| 操作 | 权限 |
| --- | --- |
| 查看、搜索需求及下载附件 | 产品经理和商务查看全部；其余账号查看直接指定给自己的需求；主管还可沿当前上下级关系查看各级下属被指定的需求。 |
| 发布需求 | 手动发布限产品经理或商务；员工、主管独立保存新 Demo 时可以自动生成需求。 |
| 编辑需求正文、分类 | 手动发布的需求限仍具有产品经理或商务角色的原发布人；Demo 自动创建的需求允许所有产品经理、商务编辑。 |
| 修改需求状态 | 产品经理或商务，可修改全部可见需求；原关闭、重开接口按需求管理权限校验。 |
| 上传需求文档、替换或移除指定人员 | 手动发布的需求限仍具有产品经理或商务角色的原发布人；Demo 自动创建的需求允许所有产品经理、商务管理。文档单文件大小沿用平台配置限制。 |
| 删除需求文档 | 所有项目经理、商务可删除可见需求的附件，不限原发布人；仅管理员、主管或员工角色均无此权限。 |
| 删除需求卡片 | 仅项目经理、商务可删除任意发布人的需求，包括 Demo 自动创建或已关闭的需求；其他角色不显示按钮，接口也拒绝操作。 |
| 转发需求并追加关联人员 | 产品经理、商务可转发给已启用的主管或员工；主管仅可转发直接指定给自己的需求给已启用的员工。 |
| 在需求中心绑定、解绑已有 Demo | 有需求管理权限的产品经理、商务；每次同时检查 Demo 可见性。Demo 编辑者在 Demo 编辑页调整关联。 |
| 查看关联 Demo、文件及说明 | 沿用现有 Demo 权限；各级上级额外获得下属所分配需求的全部关联 Demo 只读权限，包括完整说明和文件。兼任商务的上级在此范围内同样可读完整说明，其他 Demo 仍遵守原有商务字段限制。 |

绑定为多对多关系：一个需求可以关联多个 Demo，一个 Demo 最多关联 20 个需求。关系存储在 Demo 层，所有版本共用；提交和发布快照保存当时的需求信息，后续修改不覆盖历史快照。

指定人员为可选项；未指定任何人员时，只有产品经理和商务能在需求中心看到该需求。文档下载接口会独立校验当前查看权限，取消指定后立即收回该条分配带来的直接及上级继承权限；存在其他有效分配路径时仍可访问。非商务、非产品经理即使拥有 Demo 编辑权限，也无法在需求中心修改正文、状态或 Demo 绑定；被直接指定的主管可以通过转发追加员工。“项目经理”按平台现有“产品经理（pm）”角色处理。

关闭需求会阻止新的绑定，已经绑定的 Demo 保留关系并允许继续完善。待更新需求仍允许补充 Demo；重新开启时必须重新设置日程开始日期及截止日期，删除旧日程后按新日期发布新日程并通知关联人员。关闭后不再展示旧日程入口。Demo 被主管退回时，关联的进行中需求自动变为“待更新”；已交付或已关闭需求不被自动改变。具备原有绑定管理权限的人员也可以解除最后一个关联需求；原提交、发布快照仍保留当时的需求信息。

需求修改和绑定修改均检查版本号，发生冲突时拒绝覆盖；绑定操作和审计记录在同一数据库事务中提交。编辑 Demo 保存说明及需求绑定也在同一事务中完成。

项目经理、商务可在卡片或详情页点击“删除需求”，确认后该需求从需求中心、我的需求、搜索和 Excel 导出中移除，原详情、附件及回复入口失效。删除解除 Demo 绑定，保留 Demo、原文件、历史快照、审计记录和已导出的飞书文档；后续上传原 Demo 的文件不会恢复已删除需求。未发送通知和文档同步停止，关联飞书日程在后台删除，失败自动重试；可在原有日程同步管理页查看错误并重试。后台保留删除记录，平台暂不提供恢复入口。无需新增 `.env`。

## 多人转发

在“需求中心”或“我的需求”打开需求详情，点击“转发需求”，搜索并勾选多位人员，再点击“确认转发”。已关联人员显示为勾选且不可重复选择；成功后自动刷新关联人员，接收人立即可以在“我的需求”中查看需求、下载附件。

产品经理和商务可以转发全部可见需求，不要求自己是原发布人，接收人须具有主管或员工角色。仅有主管权限的账号只能转发指定给自己的需求，接收人须具有员工角色且不能兼任主管；当前可选择全部已启用员工，不限制为该主管的下属。兼任产品经理或商务的主管按合并权限可以转发给主管和员工。单独的员工、管理员没有转发权限。

每条需求最多关联 100 人。转发只追加关联，不移除已有人员，不改变发布人、需求正文、状态和附件。新增接收人的各级上级会随之获得本节说明的只读查看权限。重复人员自动去重；停用、已删除、没有接收角色的账号以及自己不可作为接收人。转发操作记录到管理审计，保留新增人员及操作人。页面打开后人员角色、启用状态或需求权限发生变化时，提交会再次校验；并发修改或转发会提示刷新，不能覆盖已有新关联。可点击“刷新人员”后重新选择并提交。

复用现有人员关联表，无需手动迁移数据或增加 `.env` 配置。更新部署时继续使用原数据卷，按 [Windows Docker 更新步骤](windows-docker-guide.md#更新当前已运行的容器并保留旧数据)备份、构建镜像并重建容器。

## 发布通知

Demo 审核通过发布、主管直接发布或恢复发布时，自动通过飞书机器人通知平台内全部已启用的产品经理，以及该 Demo 关联需求的商务发布人。多条需求对应多位商务时全部通知；同一商务发布多条需求，或同时拥有产品经理角色、被额外抄送，均只接收一条该次发布通知。产品经理和对应商务即使是本次操作人，也会收到自动通知。

“对应商务”目前按关联需求的发布人确定，且发送时仍须具有商务角色。产品经理发布的需求不会额外通知未关联的商务；如需通知其他人员，可在发布确认框中额外抄送。沿用原有归属员工通知规则，归属员工是操作人时不重复通知，兼任产品经理或对应商务时仍收到自动通知。

消息包含 Demo 名称、版本、归属员工、发布时的关联需求标题和飞书应用详情入口，不发送原始文件或成本等说明字段。关闭的需求保留原有绑定，对应商务仍属于发布通知范围；仅保存草稿、提交审核、添加绑定或修改需求不触发发布通知。

通知与发布状态在同一数据库事务中入队，发送失败不会回滚发布；复用现有失败重试、飞书 UUID 去重和管理员手动重试机制。发送前再次检查版本状态、账号是否启用、产品经理角色或商务与当前关联需求的关系，过时任务会跳过。飞书应用需已启用机器人、配置应用凭据及发送消息权限，并将接收人包含在应用可用范围内。管理员可在“平台设置 → 飞书通知”查看送达或失败记录；体验环境只验证入队，不实际发送消息，历史发布不补发。

## 更新与数据兼容

构建前端并重启后端即可加载功能，无需手动执行 SQL。启动时自动创建或更新需求相关表及索引，补充需求来源字段；现有需求标记为手动发布，管理权限保持原样。现有 Demo、文件和版本保持原样，不自动为历史数据生成需求，也不自动指定历史需求的人员。原发布人需要编辑历史需求补选人员。需求文档复用现有文件存储，数据库关系与文档一起纳入备份恢复。

当前 Windows Docker 部署按 [保留原数据卷更新步骤](windows-docker-guide.md#更新当前已运行的容器并保留旧数据)执行，使用 `compose.production.yaml` 和 `compose.keep-data.yaml` 重建镜像与容器。无需在宿主机执行下面的原生 Node.js 命令。

历史 Demo 可以继续访问，不再要求补绑需求；历史成本或数据量级为空的版本仍可编辑保存，需在下次提交／发布前补齐。新建版本沿用 Demo 的绑定关系。现有备份与恢复会包含需求和绑定关系。

```powershell
npm run build
.\scripts\stop-host.ps1
.\scripts\start-host.ps1
```

体验环境首次初始化时包含一条明确标记为合成样例的需求及其 Demo 绑定；已有体验目录也按历史数据处理，可直接在需求中心补充需求。正式环境不加入样例需求。

## 验证

自动化测试覆盖发布与管理权限、多对多绑定、Demo 访问隔离、商务绑定与内容权限隔离、提交发布校验、可选绑定、保存选填与提交时成本／数据量级必填、关闭与重开需求、并发冲突、事务回滚、备份恢复，以及发布通知接收人、去重、消息需求快照、飞书失败重试和发送前关系复核。

```powershell
npm test
npm run build
```

## 上级查看下属需求

管理员在“人员与权限 → 配置成员 → 负责主管”维护上下级关系，主管也可以设置自己的负责主管。需求直接分配或转发给某人后，沿此关系逐级向上的所有启用主管，均可在“需求中心”查看该需求；支持搜索、状态筛选、分页，以及已关闭需求。多位下属关联同一需求只显示一次。“我的需求”继续只显示直接指定给本账号的需求。

继承的查看范围包含完整需求正文、全部负责人、日期与状态、需求文档下载、平台中的日历／协作文档同步信息，以及该需求全部关联 Demo 的说明、成本、数据量级、版本记录和文件预览／下载。已下架 Demo 继续遵循原来的停止下载规则。未关联到下属需求的 Demo 不因此开放。飞书页面本身的文档／日程权限由飞书控制。

上级获得只读权限，不自动加入负责人名单，不因此获得需求修改、转发、状态管理、文件上传、Demo 编辑、审核发布、授权或导出权限。账号已有其他角色、实际审核关系或明确授权的，继续按原权限合并。需要主管转发时，将主管直接加入该需求关联人员。通知及日历邀请接收人继续使用实际关联人员与发布人。

权限按当前关系实时计算：移除需求分配、变更负责主管、停用／删除账号或断开上下级链后，对应继承路径立即失效；存在其他有效路径或独立授权时仍可访问。已有需求同样适用，无需重新发布、补写负责人或新增环境变量。配置不允许形成上下级循环；历史异常循环不会导致递归失控或经自身继承权限。

## 飞书导出文档自动同步

项目经理首次单条或批量导出成功后，后台使用文档创建者的用户授权，持续更新同一个文档的状态、名称、正文、负责人、需求附件及关联 Demo 已保存内容。无需另读 sample 或创建协作文档；旧 sample 文档保留。尚未导出的需求提示先由项目经理导出。

授权过期、退出登录或服务重启后暂停同步，原导出者重新授权并重试即可继续原链接；其他项目经理可以重新导出建立新的同步目标。文档访问权限由飞书控制，不自动增删协作者。平台管理区块之外的人工内容保留。已关闭卡片整体使用灰色，排在未关闭需求之后。配置及验收见 [需求飞书文档与 Excel 导出](requirements-export-update.md)。

## 需求回复与进展

需求内容下方提供“回复与进展”，支持普通留言、引用单条回复、搜索并 @ 多位有权查看需求的研发人员。项目经理、商务及直接关联人员可以发送；仅继承下属需求查看权限的上级只能读取回复。每条最多 5000 字、20 位提醒人员，按时间显示并支持历史分页。

被选择的 @ 人员和被回复人通过现有飞书机器人接收提醒，去重且不通知自己；发送前重新校验当前需求可见性，失效权限取消通知。回复、提醒记录和通知任务在同一事务保存，重复发送同一请求不重复建留言。回复不修改需求正文、状态或负责人，不触发建日程或文档正文同步。数据库自动升级，备份和恢复包含全部回复及提及记录。

## 样例下架后继续编辑

下架保留原发布版本为已下架状态，禁止该历史版本的文件下载和预览。若无未完成版本，自动创建一个新草稿，复用原文件及说明，保留 Demo 需求绑定，在“草稿箱”继续编辑后按原规则提交或发布。若已有草稿、退回或待审核版本，只打开现有未完成版本，不覆盖内容或创建第二份。历史下架版本提供“转到草稿继续完善”，仅编辑权限账号可用。

## 删除需求文档

在需求详情的“需求文档”列表中，项目经理、商务可点击附件右侧的“删除”，确认后立即从当前需求移除。其他角色不显示按钮，后端同样拒绝删除，包括仅管理员或主管角色；兼有项目经理或商务角色的账号按角色合并权限处理。

删除校验当前需求版本，发生并发修改时请刷新需求后重试。删除记录写入审计，已关联的飞书导出文档排队同步移除对应附件。仅解除当前需求与附件的关联，底层原文件保留，其他需求、Demo 文件和历史导出快照不受影响；原需求附件下载入口随即失效。删除不改变需求状态、负责人或已有日程。
